# Скроллинг

[План](planes.md) больше экрана, и экран показывает только его часть. Значение скролла говорит, какую именно. Чтобы сдвинуть весь слой, достаточно записать одно слово: тайлы в таблице никто не переписывает, VDP просто начинает читать таблицу с другого места.

## Как устроено

### Экран — окно, двигающееся по плану

```
Plane A, 64×32 клетки = 512×256 пикселей
┌──────────────────────────────────────────┐
│                                          │
│       ┌──────────────────────┐           │
│       │   ЭКРАН 320×224      │           │
│       │   (видимая часть)    │           │
│       └──────────────────────┘           │
│  ◄───►                                   │
│  scroll                                  │
└──────────────────────────────────────────┘
```

План [зациклен](planes.md#план-зациклен): если окно вылезает за край плана, VDP продолжает с противоположного края. Для пикселя экрана (sx, sy) берётся пиксель плана:

```
x_плана = (sx − hscroll) mod ширина_плана_в_пикселях
y_плана = (sy + vscroll) mod высота_плана_в_пикселях
```

> [!warning] Знаки разные
> Увеличение `hscroll` сдвигает картинку **вправо**, увеличение `vscroll` — **вверх**. Поэтому для камеры обычно пишут `hscroll = −cameraX`, `vscroll = cameraY`.

### Где хранятся значения

| Направление | Где | Формат |
|---|---|---|
| Горизонтальный | таблица HScroll в VRAM, адрес — [регистр](registers.md) `$0D` | пары слов `[A][B]` |
| Вертикальный | VSRAM (отдельная память VDP) | пары слов `[A][B]` |

### Режимы

Значение скролла можно задать одно на весь экран или разное для разных частей. Режимы задаются регистром `$0B`.

**Горизонтальный скролл**:

| Режим | Сколько пар `[A][B]` | Где пара для строки `n` |
|---|---|---|
| весь экран | 1 | база + 0 |
| по 8 строк (по строкам клеток) | 28 | запись первой строки полосы: база + (n / 8) × 32 |
| по каждой строке | 224 | база + n × 4 |

**Вертикальный скролл**:

| Режим | Сколько пар `[A][B]` | Где пара |
|---|---|---|
| весь экран | 1 | VSRAM `$00` (A), `$02` (B) |
| по столбцам шириной 16 пикселей | 20 (в H40) | столбец `c`: VSRAM `c × 4` (A), `c × 4 + 2` (B) |

## Как с этим работать

Скролл всего Plane A на `−cameraX` (режим «весь экран», таблица HScroll по адресу `$DC00`):

```m68k
VDP_DATA    equ $C00000
VDP_CTRL    equ $C00004

    move.l  #$5C000003, (VDP_CTRL).l    ; запись в VRAM, адрес $DC00
    move.w  CameraX, d0
    neg.w   d0
    move.w  d0, (VDP_DATA).l            ; hscroll Plane A
```

Вертикальный скролл Plane A (запись в VSRAM, адрес 0):

```m68k
    move.l  #$40000010, (VDP_CTRL).l    ; запись в VSRAM, адрес 0
    move.w  CameraY, (VDP_DATA).l
```

### Что даёт построчный скролл

- **Параллакс в одном слое**: разные полосы экрана двигаются с разной скоростью — см. [рецепт](../../cookbook/parallax.md).
- **Волны, вода, марево**: значения по строкам берутся из синусоиды.
- **Тряска экрана**: ко всем значениям добавляется ±1–2 пикселя.

### Длинные уровни

Скролл двигает окно только в пределах плана. Чтобы уровень был длиннее плана, в невидимую часть плана заранее дописывают следующие столбцы уровня — см. [Длинный уровень (подгрузка столбцов)](../../cookbook/level-streaming.md).

## Подводные камни

- Значения скролла меняют в [VBlank](timing.md) (или готовят в RAM и отправляют через [DMA](dma.md)), иначе верх и низ кадра получатся с разным сдвигом.
- Скролл двигает только планы. Window не скроллится, а спрайты имеют собственные координаты.
