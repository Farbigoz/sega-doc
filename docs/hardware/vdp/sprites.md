# Спрайты

Спрайт — подвижный объект из тайлов, который можно поставить в любую пиксельную позицию экрана, поверх или под фоном. Все спрайты описываются **таблицей спрайтов** (SAT, Sprite Attribute Table) в VRAM.

## Как устроено

### Ограничения

| | H40 | H32 |
|---|---|---|
| Спрайтов всего | 80 | 64 |
| Спрайтов на одной строке | 20 | 16 |
| Пикселей спрайтов на одной строке | 320 | 256 |

- Размер одного спрайта — от 1×1 до **4×4 тайлов** (от 8×8 до 32×32 пикселей). Объекты крупнее собираются из нескольких спрайтов.
- Если на строке больше спрайтов или пикселей, чем позволяет лимит, лишние на этой строке не рисуются. Отсюда известное мерцание: игры чередуют порядок спрайтов, чтобы пропадали каждый кадр разные.

### Запись спрайта

Каждый спрайт описывается 8 байтами (4 слова):

```
Слово 0:  ------YY YYYYYYYY        Y-координата (+128)
Слово 1:  ----WWHH -LLLLLLL        WW = ширина−1, HH = высота−1 (в тайлах), L = link
Слово 2:  P PAL V H TTTTTTTTTTT     приоритет, палитра, отражения, первый тайл
Слово 3:  -------X XXXXXXXX        X-координата (+128)
```

| Поле | Биты | Значение |
|---|---|---|
| Y | слово 0, биты 9–0 | вертикальная позиция, экранная строка 0 = 128 |
| W | слово 1, биты 11–10 | ширина: 0 = 1 тайл … 3 = 4 тайла |
| H | слово 1, биты 9–8 | высота: 0 = 1 тайл … 3 = 4 тайла |
| link | слово 1, биты 6–0 | номер следующего спрайта в списке |
| P, PAL, V, H, тайл | слово 2 | как в [слове клетки](planes.md#слово-клетки) |
| X | слово 3, биты 8–0 | горизонтальная позиция, экранный столбец 0 = 128 |

### Смещение 128

Экранная точка (0, 0) соответствует X = 128, Y = 128. Спрайт с координатой меньше 128 частично или полностью уходит за левый (верхний) край. Так объекты плавно «выезжают» из-за края экрана.

### Связный список

VDP обходит спрайты не по порядку в таблице, а по цепочке:

1. Точка входа — **спрайт 0**, первая запись по адресу таблицы спрайтов (регистр `$05`).
2. Дальше VDP переходит к спрайту с номером из поля `link`.
3. Обход заканчивается на спрайте с `link = 0`.

Порядок в цепочке задаёт и приоритет спрайтов между собой: кто раньше в списке, тот выше (см. [Приоритеты](priority.md)).

> [!warning] Спрайт 0 рисуется всегда
> Выключить спрайт 0 нельзя. Если на экране не должно быть спрайтов, спрайт 0 ставят за пределы экрана с `link = 0`.

### Порядок тайлов в спрайте

Тайлы многотайлового спрайта идут **по столбцам**: сверху вниз, затем следующий столбец. Все тайлы спрайта должны лежать в VRAM подряд, начиная с первого тайла из слова 2.

```
Спрайт 2×2, первый тайл N:      Спрайт 3×2, первый тайл N:
   N    N+2                         N    N+2   N+4
   N+1  N+3                         N+1  N+3   N+5
```

Отражение (биты H и V) отражает спрайт **целиком**, вместе с порядком тайлов.

### Спрайт-маска

Спрайт с X = 0 (экранная позиция −128) скрывает на своих строках все спрайты, идущие после него в списке. Это не ошибка, а приём: им «вырезают» спрайты в части экрана.

## Как с этим работать

Обычно таблицу спрайтов не пишут в VRAM напрямую по одному спрайту. Её копию собирают в RAM в течение кадра, проставляют цепочку `link`, а во время VBlank одной передачей [DMA](dma.md) отправляют в VRAM. Подробно — в рецепте [Буфер таблицы спрайтов в RAM](../../cookbook/sprite-table-buffer.md).

Графика тайлов спрайта должна к этому моменту уже лежать в VRAM. Если кадров анимации много, в VRAM держат только текущий кадр и подгружают его через DMA в том же VBlank.

## Примеры

Спрайт 2×2 тайла в точке экрана (100, 50), первый тайл 16, палитра 1, последний в списке:

```m68k
    dc.w 128+50             ; Y
    dc.w %0000010100000000  ; W=1 (2 тайла), H=1 (2 тайла), link=0
    dc.w $2000+16           ; палитра 1, тайл 16
    dc.w 128+100            ; X
```

## Подводные камни

- Порядок тайлов в спрайте — **по столбцам**, а не по строкам.
- Координаты со смещением **+128**.
- У последнего спрайта цепочки должен быть `link = 0`, иначе VDP пойдёт по мусору.
- Лимит спрайтов на строку: лишние пропадают без предупреждения.
