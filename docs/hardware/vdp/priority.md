# Приоритеты

Приоритеты решают, какой слой виден в каждом пикселе. Приоритет задаётся **для каждой клетки плана и каждого спрайта отдельно** — битом P. Поэтому на одном плане могут быть клетки с разным приоритетом, и спрайт может оказаться то перед ними, то за ними.

## Как устроено

Порядок слоёв, снизу вверх:

```
 Спрайты  P=1     ← верх
 Plane A  P=1
 Plane B  P=1
 Спрайты  P=0
 Plane A  P=0
 Plane B  P=0
 Цвет фона        ← низ
```

Сначала сравниваются приоритеты, и только при равном приоритете действует порядок «спрайты > A > B».

### Приоритет — у клетки, а не у плана

Спрайт с P=0 на одном и том же Plane A окажется:

- **поверх** клеток с P=0;
- **позади** клеток с P=1.

Пример: персонаж (спрайт P=0) идёт мимо колонны, у тайлов колонны P=1:

```
Plane A:  [фон P=0][фон P=0][колонна P=1][фон P=0]
Спрайт:          ───────── бежит ─────────►
Видно:    спрайт поверх фона │ за колонной │ снова поверх фона
```

Петли в Sonic сделаны именно так: часть тайлов петли помечена P=1, и персонаж «уходит» за неё.

### Прозрачность

Приоритеты работают **попиксельно с учётом прозрачности**. Прозрачный пиксель (индекс 0) клетки с P=1 ничего не закрывает: сквозь него видно то, что ниже. Если все слои в пикселе прозрачны, виден [цвет фона](palettes.md#цвет-фона-backdrop).

### Спрайты между собой

Между собой спрайты упорядочены **по связному списку**, а не по биту P: кто раньше в [списке](sprites.md#связный-список), тот выше.

> [!warning] Ловушка: низкоприоритетный спрайт впереди списка
> Пусть спрайт с P=0 стоит в списке раньше спрайта с P=1, и они пересекаются. Тогда среди спрайтов побеждает первый (P=0), и дальше этот пиксель сравнивается с планами как низкоприоритетный. Клетка плана с P=1 закроет его — и вместе с ним высокоприоритетный спрайт, который был под ним.

## Как с этим работать

- Передний план, за который должны заходить персонажи (колонны, кусты, части петель), рисуют тайлами с P=1.
- Персонажи — спрайты с P=0, если они должны уходить за такие тайлы, и P=1, если всегда должны быть сверху (например, курсор или HUD из спрайтов).
- Глубину между спрайтами задают порядком цепочки `link` при сборке [буфера спрайтов](../../cookbook/sprite-table-buffer.md).
