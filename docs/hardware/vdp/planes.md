# Планы A и B

План (plane) — это фоновый слой из тайлов. **План — не картинка, а таблица номеров тайлов.** Это похоже на мозаику: на складе лежат плитки ([тайлы](tiles.md)), а план — схема «в клетку (0,0) положить плитку №5, в клетку (1,0) — плитку №5, в клетку (2,0) — плитку №12…».

У VDP два прокручиваемых плана, **Plane A** и **Plane B**, и неподвижный слой [Window](window.md). Все они устроены одинаково и берут тайлы с одного и того же склада.

## Как устроено

### Где лежит план

В VRAM одновременно находятся тайлы и таблицы планов. Для VDP это просто байты. Где какая таблица, вы сообщаете [регистрами](registers.md): «Plane A начинается с `$C000`» (регистр `$02`), «Plane B — с `$E000`» (регистр `$04`).

```
VRAM (64 КБ)
┌──────────────────────────────┐ $0000
│ Тайлы (по 32 байта)          │  ← «склад плиток»
│ тайл 0, тайл 1, тайл 2 ...   │
├──────────────────────────────┤ $C000
│ Таблица Plane A              │  ← «схема мозаики» слоя A
├──────────────────────────────┤ $E000
│ Таблица Plane B              │  ← «схема мозаики» слоя B
├──────────────────────────────┤
│ Window, спрайты, HScroll     │
└──────────────────────────────┘ $FFFF
```

Пример полной раскладки — на странице [Раскладка VRAM](vram-layout.md).

### Таблица имён

Таблица плана называется **таблицей имён** (nametable, tilemap). Это двумерный массив слов, по одному слову на клетку 8×8, записанный построчно:

```
План 64×32 клетки, база $C000:

Адрес            Клетка
$C000 + 0        (0, 0)
$C000 + 2        (1, 0)
...
$C000 + 126      (63, 0)    ← конец первой строки
$C000 + 128      (0, 1)     ← начало второй строки
...
```

```
адрес клетки (x, y) = база + (y × ширина_плана + x) × 2
```

### Слово клетки

```
 15 | 14 13 | 12 | 11 | 10 .......... 0
  P |  PAL  | V  | H  |  номер тайла
```

| Поле | Биты | Значение |
|---|---|---|
| P | 15 | [приоритет](priority.md): 1 — поверх низкоприоритетных слоёв |
| PAL | 14–13 | [палитра](palettes.md) 0–3 |
| V | 12 | отражение по вертикали |
| H | 11 | отражение по горизонтали |
| номер тайла | 10–0 | 0–2047 |

Пример: `$A005` = приоритет 1, палитра 1, без отражений, тайл 5:

```
(1 << 15) | (1 << 13) | 5  =  $8000 + $2000 + $0005  =  $A005
```

### Размеры планов

Регистр `$10` задаёт ширину и высоту планов A и B в клетках: **32, 64 или 128** по каждой оси. Таблица не может быть больше 8 КБ (4096 клеток), поэтому допустимы:

| Размер | Пикселей | Таблица |
|---|---|---|
| 32×32 | 256×256 | 2 КБ |
| 64×32 | 512×256 | 4 КБ |
| 32×64 | 256×512 | 4 КБ |
| 128×32 | 1024×256 | 8 КБ |
| 64×64 | 512×512 | 8 КБ |
| 32×128 | 256×1024 | 8 КБ |

128×128 и 128×64 недопустимы.

Выбор размера — компромисс:

- больший план даёт больше невидимого запаса за краем экрана (реже подгрузка, можно скроллить быстрее, больше места для эффектов), но занимает больше VRAM, которая нужна тайлам;
- игра со скроллом по горизонтали — часто 64×32;
- игра со скроллом по вертикали — 32×64 или 64×64;
- экран в режиме H40 шириной 40 клеток, поэтому для горизонтального скролла ширина 32 не подходит: план должен быть шире экрана.

### План зациклен

План больше экрана, и экран показывает только его часть — какую именно, задаёт [скролл](scrolling.md). Если видимая часть выходит за правый край плана, VDP продолжает с левого края, а за нижним краем снова идёт верхний. На этом построены [бесконечные уровни](../../cookbook/level-streaming.md).

### Plane A и Plane B

Планы устроены одинаково, различия такие:

- при одинаковом приоритете Plane A рисуется **поверх** Plane B;
- Plane A в части экрана может заменяться слоем [Window](window.md).

Обычно B — дальний фон (небо, горы), A — передний план (земля, платформы). Каждый план скроллится независимо, и за счёт разной скорости получается [параллакс](../../cookbook/parallax.md).

## Как с этим работать

Нарисовать тайл №1 в клетке (5, 3) Plane A (база `$C000`, ширина 64):

1. Адрес клетки: `$C000 + (3 × 64 + 5) × 2 = $C18A`.
2. Слово клетки: приоритет 0, палитра 0, без отражений, тайл 1 → `$0001`.

```m68k
VDP_DATA    equ $C00000
VDP_CTRL    equ $C00004

    move.l  #$418A0003, (VDP_CTRL).l    ; запись в VRAM, адрес $C18A
    move.w  #$0001, (VDP_DATA).l
```

Как из адреса `$C18A` получилось `$418A0003`, разобрано в [Портах и командах](ports-and-commands.md#пример-разбора).

Записать целую строку клеток можно подряд: [автоинкремент](ports-and-commands.md#автоинкремент) сам сдвигает адрес. Для записи столбца ставят автоинкремент, равный ширине строки таблицы в байтах (128 для ширины 64).

## Подводные камни

- Таблица плана хранит **номера** тайлов. Чтобы изменить картинку, меняют номера в таблице, а не графику тайлов.
- Пустые клетки (слово `$0000`) показывают тайл 0. Его оставляют прозрачным.
