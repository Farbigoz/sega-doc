# DMA

DMA (Direct Memory Access) — быстрая передача данных в память VDP без участия процессора в каждом слове. Через DMA грузят тайлы, палитры, таблицу спрайтов и скролл. Цикл из `move` в порт данных намного медленнее.

## Как устроено

### Виды DMA

| Вид | Что делает |
|---|---|
| Из памяти 68000 | копирует данные из ROM или RAM в VRAM, CRAM или VSRAM. Основной вид |
| Заполнение (fill) | заполняет область VRAM одним значением, например для очистки |
| Копирование (copy) | копирует данные внутри VRAM |

### Регистры

| Регистр | Значение |
|---|---|
| `$13` | длина в **словах**, младший байт |
| `$14` | длина в словах, старший байт |
| `$15` | адрес источника / 2, биты 7–0 |
| `$16` | адрес источника / 2, биты 15–8 |
| `$17` | адрес источника / 2, биты 22–16, и вид DMA в старших битах |

DMA должен быть разрешён битом 4 [регистра](registers.md) `$01`. Передача начинается командой адреса с установленным битом CD5 (см. [коды операций](ports-and-commands.md#коды-операций)): для записи в VRAM это `| $80` во втором слове команды.

### Пропускная способность

- Во время [VBlank](timing.md) VDP не читает VRAM для изображения, и через DMA успевает пройти около **7 КБ за кадр** (H40, NTSC).
- Во время активной отрисовки — почти ничего.

Поэтому обновления VRAM копят в буфере в RAM и отправляют через DMA в начале VBlank.

### Ограничение 128 КБ

Ограничение касается **источника**, а не VRAM. Во время передачи VDP наращивает только младшие 16 бит адреса источника в словах (регистры `$15`–`$16`), то есть 17 бит в байтах = 128 КБ. Регистр `$17` не меняется.

Если блок в ROM начинается на `$1FFF00` и длится 512 байт, после `$1FFFFE` адрес перескочит не на `$200000`, а на `$1E0000` — в начало того же 128-КБ блока. Скопируется мусор.

Решения:

- выравнивать данные в ROM так, чтобы блок не пересекал границу, кратную `$20000`;
- разбивать передачу на две части по границе.

### Процессор стоит

Во время DMA из памяти 68000 шина занята, и процессор ждёт окончания передачи.

## Как с этим работать

Макрос: копировать `LEN` слов из `SRC` (ROM/RAM 68000) в VRAM по адресу `DEST`. Все параметры — константы времени сборки:

```m68k
VDP_CTRL    equ $C00004

DMA_TO_VRAM macro SRC, DEST, LEN
    move.w  #$8F02, (VDP_CTRL).l                        ; автоинкремент 2
    move.w  #$9300|((\LEN)&$FF), (VDP_CTRL).l           ; длина, младший байт
    move.w  #$9400|(((\LEN)>>8)&$FF), (VDP_CTRL).l      ; длина, старший байт
    move.w  #$9500|(((\SRC)>>1)&$FF), (VDP_CTRL).l      ; источник / 2, биты 7–0
    move.w  #$9600|(((\SRC)>>9)&$FF), (VDP_CTRL).l      ; биты 15–8
    move.w  #$9700|(((\SRC)>>17)&$7F), (VDP_CTRL).l     ; биты 22–16, вид: из памяти
    move.l  #$40000080|(((\DEST)&$3FFF)<<16)|((\DEST)>>14), (VDP_CTRL).l  ; запись в VRAM + DMA
    endm
```

### Очередь DMA

Обычная практика: за кадр в очередь в RAM складываются запросы «что, куда, сколько», а обработчик VBlank выполняет их все подряд. Так в VRAM попадают таблица спрайтов, скролл, палитры и новые кадры анимации.

## Подводные камни

- Источник не должен пересекать границу 128 КБ.
- Длина задаётся в **словах**, а не в байтах.
- Большие передачи вне VBlank идут очень медленно и могут «рвать» кадр.
