# Длинный уровень (подгрузка столбцов)

**Задача:** уровень длиной в тысячи пикселей, а [план](../hardware/vdp/planes.md) — всего 512. **Решение:** план работает как кольцевой буфер. По мере движения камеры в его невидимую часть дописываются следующие столбцы уровня. Переписываются **номера тайлов в таблице имён**, а не графика тайлов.

## Идея

План 64 клетки = 512 пикселей, экран — 320. Справа за экраном остаётся невидимый запас 192 пикселя (24 столбца). Пока камера движется, туда заранее дописывается следующий столбец уровня. План [зациклен](../hardware/vdp/planes.md#план-зациклен), поэтому столбец уровня `n` пишется в столбец таблицы `n mod 64`:

```
Карта уровня в ROM (например, 2000 столбцов):
[0][1][2][3] ... [40][41][42][43] ... [1999]

Таблица Plane A (64 столбца, зациклена):
столбец таблицы = столбец уровня mod 64

Камера на столбце 30:
┌─────────────────────────────────────────────────────┐
│ ...[30 ... 69 видны на экране]... [70][71] ... запас │
└─────────────────────────────────────────────────────┘
```

Старые столбцы, ушедшие за левый край, затираются новыми.

## Алгоритм

1. Камера сдвинулась и пересекла границу клетки (каждые 8 пикселей).
2. Берём столбец уровня `(cameraX + 320) / 8` из карты в ROM.
3. Пишем его клетки в столбец таблицы `номер mod 64`.
4. Ставим `hscroll = −cameraX` ([скролл](../hardware/vdp/scrolling.md)); зацикливание плана сделает остальное.

Влево — то же самое со столбцом `cameraX / 8 − 1`. По вертикали аналогично, только дописываются строки.

## Код

Запись столбца из 32 клеток в Plane A (база `$C000`, ширина 64). [Автоинкремент](../hardware/vdp/ports-and-commands.md#автоинкремент) 128 — длина строки таблицы в байтах: каждая запись попадает на строку ниже в том же столбце.

```m68k
VDP_DATA    equ $C00000
VDP_CTRL    equ $C00004

; a0 — 32 слова клеток столбца уровня
; d0 — номер столбца в таблице плана (0–63)
WriteColumn:
    move.w  #$8F80, (VDP_CTRL).l    ; автоинкремент 128
    move.w  d0, d1
    add.w   d1, d1                  ; столбец × 2
    add.w   #$C000, d1              ; d1 = адрес клетки (столбец, 0)
    move.w  d1, d2
    and.w   #$3FFF, d1
    or.w    #$4000, d1              ; первое слово: запись VRAM, A13..A0
    rol.w   #2, d2
    and.w   #3, d2                  ; второе слово: A15..A14
    move.w  d1, (VDP_CTRL).l
    move.w  d2, (VDP_CTRL).l
    moveq   #32-1, d3
.loop:
    move.w  (a0)+, (VDP_DATA).l
    dbra    d3, .loop
    move.w  #$8F02, (VDP_CTRL).l    ; вернуть автоинкремент 2
    rts
```

Логика выбора столбца на C (без привязки к библиотеке):

```c
#define SCREEN_W  320
#define PLANE_W   64      // ширина плана в клетках

static s16 lastStreamedCol = -1;

// Вызывается каждый кадр после движения камеры.
void streamColumns(s32 cameraX)
{
    s16 col = (cameraX + SCREEN_W) / 8;   // столбец уровня, который скоро появится справа

    while (lastStreamedCol < col) {       // за кадр камера могла пройти больше 8 пикселей
        lastStreamedCol++;
        writeColumn(lastStreamedCol % PLANE_W, levelColumn(lastStreamedCol));
    }
    hscrollA = -cameraX;
}
```

## Подводные камни

- Если камера за кадр проходит больше 8 пикселей, нужно дописать несколько столбцов, а не один.
- Запись в таблицу имён лучше делать в VBlank или через буфер и [DMA](../hardware/vdp/dma.md). Тогда новый столбец не появится на экране «наполовину».
- Скорость камеры ограничена запасом плана: за кадр нельзя уехать дальше, чем успеваешь дописать.
- Карту уровня в ROM обычно хранят не по тайлам, а блоками (например, 16×16 из тайлов, крупные куски из блоков) — это экономит ROM.
