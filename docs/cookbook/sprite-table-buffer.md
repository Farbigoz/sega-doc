# Буфер таблицы спрайтов в RAM

**Задача:** обновлять десятки [спрайтов](../hardware/vdp/sprites.md) каждый кадр быстро и без дёрганий. **Решение:** держать «теневую» копию таблицы спрайтов в RAM, заполнять её в течение кадра, а во время VBlank отправлять в VRAM одной передачей [DMA](../hardware/vdp/dma.md).

## Идея

```
RAM 68000                                VRAM
┌──────────────────────────┐   DMA в    ┌────────────────────┐
│ теневая таблица спрайтов │  VBlank    │ таблица спрайтов   │
│ (до 640 байт)            │ ─────────► │ (SAT)              │
│ Y, размер, link, тайл, X │            └────────────────────┘
└──────────────────────────┘
```

1. В течение кадра игровая логика пишет в буфер координаты всех объектов, номера тайлов (кадр анимации) и отражения.
2. При заполнении проставляется [цепочка link](../hardware/vdp/sprites.md#связный-список): 1 → 2 → 3 → … → последний с `link = 0`. Порядок цепочки задаёт глубину спрайтов.
3. В VBlank буфер уходит в VRAM одним DMA. 640 байт — небольшая доля пропускной способности VBlank.

Плюсы:

- работа с RAM быстрая и возможна в любой момент кадра;
- VDP никогда не видит наполовину обновлённую таблицу.

## Код

Сборка буфера из списка объектов:

```m68k
SpriteBuf   equ $FF0000     ; 80 × 8 байт в RAM

; a0 — список объектов, на объект 8 байт: x.w, y.w, attr.w, size.w
;      size — биты размера WWHH, уже сдвинутые в биты 11–8
; d7 — количество объектов (1–80)
BuildSprites:
    lea     SpriteBuf, a1
    moveq   #1, d6              ; link следующего спрайта
    subq.w  #1, d7
.loop:
    move.w  2(a0), d0
    add.w   #128, d0
    move.w  d0, (a1)+           ; слово 0: Y
    move.w  6(a0), d0
    or.w    d6, d0
    move.w  d0, (a1)+           ; слово 1: размер и link
    move.w  4(a0), (a1)+        ; слово 2: P, палитра, отражения, тайл
    move.w  (a0), d0
    add.w   #128, d0
    move.w  d0, (a1)+           ; слово 3: X
    addq.w  #1, d6
    addq.l  #8, a0
    dbra    d7, .loop
    and.w   #$FF00, -6(a1)      ; у последнего спрайта link = 0
    rts
```

Отправка в VBlank (макрос `DMA_TO_VRAM` — со страницы [DMA](../hardware/vdp/dma.md#как-с-этим-работать)), таблица спрайтов по адресу `$D800`:

```m68k
VBlankHandler:
    ; ...
    DMA_TO_VRAM SpriteBuf, $D800, 80*4     ; 80 спрайтов × 4 слова
    ; ...
    rte
```

В SGDK то же самое делают `SPR_update()` (готовит таблицу) и `SYS_doVBlankProcess()` (ждёт VBlank и выполняет DMA).

## Подводные камни

- У последнего спрайта должен быть `link = 0`.
- Если объектов нет, спрайт 0 всё равно рисуется — его ставят за экран.
- Отправлять можно не всю таблицу, а только использованные записи: `количество × 4` слов.
- Графика тайлов спрайтов должна уже лежать в VRAM. Новые кадры анимации подгружаются через DMA в том же VBlank.
